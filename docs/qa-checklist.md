# M5 최종 검수 (PLAN.md 11번 체크리스트 기준)

이 세션에는 브라우저 자동화 도구가 로드되어 있지 않아, **코드 검토와 단위 테스트로 확인 가능한 항목은 직접 검증**했고, **실제 클릭/두 계정 테스트가 필요한 항목은 사용자가 확인**해야 합니다. 표의 "검증 방법"을 참고해 주세요.

| # | 항목 | 상태 | 검증 방법 |
|---|---|---|---|
| 1 | 새 계정 가입 → 할 일 추가 → 체크 → 로그아웃 → 재로그인 시 데이터 유지 | ⏳ 사용자 확인 필요 | 데이터가 Supabase Postgres에 저장되고 세션 쿠키로만 인증 상태를 유지하므로 구조상 유지되는 게 맞지만, 실제 로그아웃→재로그인 클릭 테스트는 못 해봤습니다. |
| 2 | 다른 계정으로 로그인 시 남의 데이터 안 보임(RLS) | ⏳ 사용자 확인 필요(권장) | `supabase/migrations/0005_rls_policies.sql`에 모든 테이블 `auth.uid() = user_id` 정책 확인함(코드 검토 완료). 실제 두 계정으로 교차 확인하는 걸 강력 추천합니다 — 계정 2개 준비해서 각자 할 일을 만들고 서로 안 보이는지 확인해주세요. |
| 3 | 23:50 / 00:10 체크 시 날짜 집계 | ✅ 검증 완료 | `src/lib/date/__tests__/local-date.test.ts`에 정확히 이 두 시각 케이스가 단위 테스트로 있고 통과함. 루틴 체크는 체크하는 "그 순간" 기준으로 날짜가 정해지고, 할 일은 생성 시점 기준으로 날짜가 고정된 뒤 체크 여부만 바뀌는 구조라 일관됩니다. |
| 4 | 루틴 수정·보관해도 과거 잔디 기록 유지 | ✅ 검증 완료(코드 검토) | `updateRoutine`/`setRoutineArchived`는 `routines` 테이블만 수정하고 `routine_logs`(그날의 기록)에는 손대지 않음. `/stats`의 루틴별 달성률에는 보관된 루틴도 계속 포함됨. (참고: UI에 "삭제" 버튼은 없고 "보관"만 있음 — PLAN.md 화면 명세와 동일) |
| 5 | 신규 빈 계정에서 모든 화면 정상 | ✅ 검증 완료(코드 검토) | `/today`, `/routines`, `/stats` 모두 데이터 0건일 때의 빈 상태 문구/화면을 명시적으로 분기 처리함. 서버 쿼리들도 빈 배열을 정상 처리하도록 작성됨. |
| 6 | 375px/태블릿/데스크탑 레이아웃 | ⏳ 사용자 확인 권장 | 앱 화면은 `max-w-md` 중앙 정렬(모바일 우선), 랜딩은 더 넓게 설계. 코드 레벨로 overflow/truncate 점검은 했지만 실기기 확인은 못 했습니다. |
| 7 | 오프라인 상태에서 체크 시 적절한 오류 안내 | ✅ 검증 완료(이번 세션에서 버그 발견 후 수정) | 서버 액션 호출 자체가 실패하는 경우(네트워크 단절)를 잡지 못하던 버그를 발견해 `src/lib/safe-action.ts`로 모든 클라이언트 액션 호출을 감싸도록 수정함. 이제 오프라인 시에도 "네트워크에 문제가 있는 것 같아요..." 토스트가 뜨고 낙관적 업데이트가 자동으로 롤백됨. |
| 8 | 키보드만으로 할 일 추가·체크·삭제 | ✅ 검증 완료(코드 검토) | 입력창은 일반 `<form>`+Enter 제출, 체크박스/삭제 버튼은 전부 네이티브 포커스 가능 요소(Base UI 접근성 기본 지원), 드래그 정렬은 dnd-kit `KeyboardSensor` 추가되어 있음. 실제 Tab/Enter만으로 끝까지 조작해보는 걸 권장합니다. |
| 9 | 데모 모드가 로그인 없이 완전히 동작 | ✅ 검증 완료 | `/demo`는 `proxy.ts`의 보호 경로 목록에 없어 비로그인 접근 가능함을 확인(curl로 200 응답 확인). 추가/체크/수정/삭제/순서변경 전부 로컬 state로 동작, 서버 호출 없음. |

## 요약

- **코드/테스트로 검증 가능한 6개 항목은 확인 완료**했고, 그 과정에서 오프라인 에러 처리 버그(#7)를 하나 발견해 고쳤습니다.
- **실제 클릭 조작이나 두 계정이 필요한 3개 항목(#1, #2, #6)은 사용자가 직접 확인**해주셔야 최종적으로 "완료"라고 말할 수 있습니다. 특히 #2(RLS 교차 확인)는 개인정보 보호의 핵심이라 꼭 한 번 해보시는 걸 권장드립니다.
